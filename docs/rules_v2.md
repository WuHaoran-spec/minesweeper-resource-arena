# 大棋盘挑战规则：arena-v2.0

v2 是针对实际试玩反馈新增的长局挑战模式：扩大棋盘与资源数，增加有限生命和复活，并开启零区展开。它与历史 `arena-v1.0` 分开编号；v1 的规则、模型和实验仍按[原规则](rules.md)解释，不能合并成同一结果。权威预设位于 `arena/config.py`，机器可读摘要见 `config/rules_v2.json`。

| 争夺预设 | 宽×高 | 地雷 | 钻石 | 每方初始生命 | 总行动上限 |
|---|---:|---:|---:|---:|---:|
| intermediate | 16×16 | 40 | 7 | 3 | 800 |
| expert | 30×16 | 99 | 11 | 3 | 1600 |

宽和高必须分别处理；扁平数组索引为 `row * width + column`。兼容字段 `size` 等于宽，不表示棋盘一定为正方形。四邻接移动与八邻域数字均按矩形边界检查，不得在行尾与下一行之间错误连边。

## 地图先验与开局

两起点为左上角 `(0,0)` 和右下角 `(height-1,width-1)`。两角各有预定的 3×3 安全区；其全部格子公开加入已知安全集合。先从安全区以外、且到任一起点曼哈顿距离均不小于 6 的格子中均匀选择互异钻石，再从排除安全区和全部钻石后的其余格子均匀抽取固定数量地雷。钻石公开且安全；全局固定雷数不变，生成后不随行动移雷。

这些安全区与钻石距离限制是公开的生成规则，用于避免贴近起点的立即送分和无操作空间开局；不是跑出地图后按胜率或可达性筛选。不会保证全部钻石可达，也不会保证双方每图公平。换座仅交换玩家起点身份，换先手仅改变第一个行动者，同一基础地图保持不变。分集合去重只排除相同／几何等价基础图的跨集合重复，不筛选有利结果。

初始化从双方起点执行零区展开；每次到达安全格也展开与其相连的零区及边缘数字。公开观察包含这些真实揭示结果，推断器使用公开安全条件。展开只是揭示信息，不能远程拿钻石：即使某颗钻石已被零区揭示，其分数仍须角色实际走到该格才取得。

## 行动、生命与胜负

双方轮流执行上、下、左、右移动一格，或等待。每次合法行动，包括等待和踩雷，共消耗一步。双方允许穿过或共占安全格。动作合法性只依赖矩形边界与已公开爆雷格；实际有雷但尚未揭示的格子仍然合法，不能通过动作掩码向策略泄露真值。

首次到达剩余钻石格获得 1 分并移除钻石，不重复计分。踩雷消耗 1 条生命，该地雷公开标记且永久留在原位置；已有得分不减少。若仍有生命，角色立即回到属于自己的开局角落，随后由另一名存活者行动；若另一方已淘汰，则此存活者继续行动。生命减为 0 时永久停止行动，位置保留在最后爆雷格，后续轮次跳过。已公开爆雷格不能再次进入；复活不重新生成地图或恢复钻石。

终局条件按以下顺序检查：钻石全部取完、双方均无生命、达到总行动上限。只比较双方钻石数，同分平局；存活、剩余生命、揭格数和行动耗时不另加游戏得分。领先者即使淘汰仍可能按分数获胜。不会使用隐藏雷图预测“未来无人能取到资源”而提前结束；不可达、等待循环、失败和平局照常保留，上限保证有限终止。

非法输入不改变状态；暂停是调度状态，不消耗行动步。重置或恢复后的旧请求由会话标识和观察版本拒绝。主模式右键人工标记只属于界面及回放注释，不会被当作实际地雷，也不参与概率推断或动作掩码。

## 公开接口和复盘

`Arena(seed, first=0, swap=False, preset='intermediate')` 或 `preset='expert'` 使用上述默认上限；显式 `max_steps` 可覆盖上限，正式评测必须记录该值。`Arena(seed)` 默认保持历史 v1 行为。重置时切换预设会采用新预设默认上限，除非显式传入上限。

v2 公开观察保留 v1 字段，并增加 `width`、`height`、`resource_count`（初始钻石总数）、`lives`（双方剩余生命）和 `preset`；`rule_version` 为 `arena-v2.0`。`known_safe` 保留已领取钻石的安全事实。隐藏雷图、地图种子、将来结果和对手内部状态不传给决策器；终局争夺观察仍不补发整张雷图。

大棋盘风险计算另有固定运算预算：超过 81 格时，每次观察最多执行 50,000 次子集约束配对比较，防止在模型枚举之前无限增长。达到预算只停止额外冗余推导，原始线索约束全部保留；若后续每分量不超过 23 格、30,000 搜索节点的完整枚举成功，后验仍可标为精确。枚举超限则明确标为近似。详情同时记录子集比较次数、预算是否耗尽及保留约束数。这是训练前冻结的运算约束，不是按地图结果挑选样本；旧 v1 的计算路径与诊断格式保持不变。

公开回放沿用已有容器格式 `arena-public-replay-v1`，其中各局面的规则版本明确为 v2；不能根据容器名称把它当成旧规则。爆雷反馈记录 `life_lost`、`respawned` 和 `lives_after`。私有快照为 `arena-private-snapshot-v2`，保存预设配置、真实状态和观察中的实际行动上限；仅供可信后端恢复，不发给策略或公开仓库。

## 与 Windows 风格经典扫雷的区别

经典新预设为 beginner（9×9、10 雷）、intermediate（16×16、40 雷）和 expert（30×16、99 雷）。`Classic(seed,preset=...)` 使用 `classic-v2.0`：首次揭格时才均匀放雷，排除首格及棋盘内八邻域；因此首击与周围格安全，并正常零区展开。插旗不会改变真实雷位，未去旗的格子不能直接揭开。

对已揭示正数字执行双击／连开时，只有周围旗标数等于该数字才打开其余未揭、未插旗邻格；错旗也可能满足数量并导致踩雷。经典模式揭完全部安全格获胜，踩雷失败；仅在经典失败终局显示全部雷位。经典模式没有角色移动、钻石计分或复活机制。直接 `Classic(seed)` 仍保留旧版固定雷、首击可能失败及旧观察格式，用于历史回归。

大尺寸和交互方式参考常见经典扫雷体验，但三条生命、返回起点、逐格行走和公开资源争夺属于本项目变体，不冒称 Windows 经典规则。v2 需要对应的新策略特征和训练权重；旧版 27 维网络的实验结论不能自动迁移到新棋盘。

## 本轮引擎验证

`python -m unittest discover -s tests -p test_engine_v2.py -v` 覆盖矩形边界、数字、安全区先验、钻石距离、有限生命、复活后的行动者、得分保留、隐藏信息与合法掩码、快照一致性、默认预设切换、安全首击、正确／错误旗标连开及经典胜负。历史 `test_env.py` 的 22 项测试继续通过。另将旧版实现与新实现的 legacy 模式在 10 张基础图、356 次相同动作上逐步对照，公开观察、公开回放与私有快照完全一致（对齐独立随机局号后比较）。这些是规则回归证据；训练数据质量与策略性能另由挑战实验记录说明。
