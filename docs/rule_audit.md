# v1.0 规则及信息边界审查

审查日期：2026-09-30。对象为 `arena-v1.0`，不改变冻结规则、不筛除不利地图。规则人工核对、构造回归测试、随机地图静态检查分别记录，不把设计判断当作胜率实测。

## 规则允许的现象

| 现象 | 归类与处理 | 已完成证据 |
|---|---|---|
| 钻石紧邻某一起点，一步即可获得 | 均匀抽样允许的地图差异；保持原样。不是预先送分，仍须实际到达 | 领取唯一性和未到不计分测试；下述静态地图审查 |
| 双方等距离争同一钻石时先行动者可先到 | 轮流机制允许的先手效应；交换身份和先手评测，不声称每图公平 | 固定地图在换座/先手下不变的测试；具体胜率由正式评测报告给出 |
| 领先者淘汰后仍然获胜 | 得分保留、仅比较钻石的合法结果；不改为存活者自动胜 | 回归案例：A 先得 1 分再踩雷，B 存活，达到上限后 A 以 1:0 获胜 |
| 领先者等待、避险或冒险，策略未按预期继续争夺 | 可能是合法策略，也可能是学习不足；须结合公开状态和终局核验 | 等待计步、200 步终局、淘汰跳过测试；没有声称训练已学会故意自我淘汰 |
| 部分钻石不可达、起点出口均有雷 | 未筛选地图的正常结果；保留失败/超时，不重新生成地图 | 静态可达性审查；100 个地图随机合法动作完整终局测试 |
| 人工旗标可能插错 | 只作显示标记，不是推断事实 | Session 测试比较插旗前后观察、后验和 B2 决策，均相同 |

3 个钻石不保证每局无平局：资源可能未取完。固定对角起点和均匀抽样具有几何上的对称性，但单张地图及首手都可能不对称；几何对称不等于实测胜率相等。

## 1,000 张额外审查地图的静态检查

本次重新执行了 1,000 张专用审查地图的检查，非训练、验证、初测或复测样本。该审查的地图序列和脚本保留在私人交付目录，不随公开记录披露种子。检查只读私有环境真值以核验地图结构，不向策略提供这些真值，也不据此筛选任何实验地图。

| 静态事件 | 地图数 / 1,000 |
|---|---:|
| 至少一颗钻石位于任一起点的四邻接格 | 148 |
| 至少一颗钻石从两个起点的安全格连通域均不可达 | 4 |
| 至少一个起点的两个初始出口均布雷 | 28 |

任一起点周围共有 4 个互不重叠的候选邻格。按本项目抽样先验，至少一颗钻石在这 4 格中的概率为 `1 − C(75,3) / C(79,3) = 0.1461070575`。148/1000 与此数量级一致，但这不是算法效果测试。不可达性使用四邻接安全格图，不计算策略在未知信息下是否能找到路线。

静态检查核心步骤如下。`audit_maps` 由可信审查程序私下提供，不能作为策略输入；对任意新随机序列运行会得到不同频数，本表只对应上述本次固定样本。

```python
from arena.env import Arena, STARTS
from collections import deque

counts = [0, 0, 0]
for seed in audit_maps:
    env = Arena(seed)  # 私有真值仅在离线规则审查中使用
    counts[0] += bool(env._diamonds & {(0,1),(1,0),(7,8),(8,7)})
    counts[2] += ({(0,1),(1,0)} <= env._mines or
                  {(7,8),(8,7)} <= env._mines)
    seen, queue = set(STARTS), deque(STARTS)
    while queue:
        r, c = queue.popleft()
        for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
            cell = r+dr, c+dc
            if (0 <= cell[0] < 9 and 0 <= cell[1] < 9
                    and cell not in seen and cell not in env._mines):
                seen.add(cell)
                queue.append(cell)
    counts[1] += bool(env._diamonds - seen)
print(counts)
```

## 已修复的实现问题

这些是实现可靠性问题，修复未改变胜负、布雷先验或行动规则。

1. Session 原先在完整验证重置参数之前改变了当前模式和棋盘。现先验证并构建新环境，再整体替换；非法重置保留原对局、日志和旗标。
2. 旧版快照接口未检查观察版本。现动作、快照和恢复均检查当前会话 epoch 与 revision；重置和恢复生成新的 epoch。
3. 快照恢复原先残留后续对局旗标。现恢复保存时的旗标和策略随机状态；后续记录明确标为 `counterfactual_replay`。快照最多在服务内存保存 100 个，超过后移除最早一个。
4. AI 动作原先缺少交互来源标记。现每条 AI 元数据保留 `source`，并区分 `heuristic_policy` 与 `learning_policy`。自动化点击即使走人工输入接口，仍标记 `browser_automation`，不计作真实人类数据。
5. 导出界面帧原先遗漏旗标操作。现旗标变化也保存帧，显示注释放入 `ui_flags`；该字段不进入环境观察、约束推断或策略输入。
6. Session 返回值原先可通过 Python 对象引用间接改写控制器或诊断。现返回独立副本。
7. 风险推断曾忽略部分矛盾的空约束，可能对不可能的外部观察错误标记精确。现检查坐标、线索范围、重复冲突、安全／地雷矛盾、空约束和全局雷数一致性；拒绝矛盾观察。有效游戏状态的后验不变，截断诊断额外计入已执行的搜索节点。

## 风险推断与策略边界

`risk.py` 与 `policies.py` 的输入为公开观察；服务器传入其副本。环境隐雷只能由权威规则在真正落格时结算；动作掩码只查看边界与公开爆雷。

本次新增独立检查使用 600 个 3×3／4×4 公开局面，变化雷数、已知安全条件、揭示范围和已爆雷事实；穷举所有兼容组合，逐格后验和模型数量均与推断模块一致，概率绝对误差小于 1e-12。参考枚举器使用独立的邻域实现。另明确检查不连通组件的全局雷数权重、人工旗标不作事实、缓存副本隔离、畸形输入拒绝，以及大前沿必须标记近似。

另外实际运行 400 张额外随机地图，共核验 15,696 次行动前公共观察：概率均在 [0,1]，已知安全格概率均为 0；本批均完成精确计算，所有格概率之和等于 10。此冒烟批次不构成策略效果评测，不表示所有大前沿都能精确求解；专门构造的大前沿测试实际返回 `approximate_cutoff`。上述有限核验不代替任意规模的形式证明。

B1 在改变对手位置、得分和生存状态后决策不变；移除对手信息的学习特征在这些变化下也不变。这里的消融准确含义是移除**显式对手状态特征**：共享已揭线索仍可由双方历史行动形成，不能宣称消除了对手造成的全部信息。

路径成本是边缘风险的加性启发式代价，不是严格的整条路径成功概率。学习策略的展示目标是由选中动作推断出的诊断目标，未伪装成模型显式目标头或主观意图。
